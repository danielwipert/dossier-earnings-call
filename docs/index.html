Design Principles

Architectural commitments

These are load-bearing constraints, not preferences. Every pipeline decision traces back to one of them.

Core commitment: trust is structural, not a model property. Every factual claim in the output traces back to a verbatim quote from the transcript through an immutable FactList. Nothing advances between stages without a governance gate check.

01
No unverified output

If the verification pipeline is unavailable, halt. There is no fallback to unverified generation. A system that sometimes verifies is not a verified system.

02
FactList immutability

The FactList is locked after Gate 1a passes. No downstream agent may add, modify, or remove facts. Trust is established once and cannot be retroactively altered.

03
Multi-family verification

Generation and verification always use different model families. A model that generates a hallucination and verifies it is structurally equivalent to no verification.

04
No investment advice

S5 scans for buy / sell / hold language. If found, immediate Level 3 halt — no report released. The system produces analysis, never recommendations.

05
Verbatim grounding

Every FactList entry requires a character-exact verbatim_quote from the transcript. If a quote cannot be confirmed, the fact is rejected at Gate 1a — not softened.

06
Observed observation

Every report discloses what the verification system can and cannot catch. The system observes its own observation process — a second-order cybernetic commitment.

Core Concept

The FactList — immutable foundation

The FactList is the single source of truth for every claim in the report. It is created once, validated by Gate 1a, and locked forever. No downstream agent may add, modify, or remove facts.

Final report claim ↓ (S2 claim cites source_fact_ids) FactList entry F012 verbatim_quote: "adjusted EPS increased 16 percent year-over-year" speaker: "Raj Subramaniam, President and CEO" ↓ (Gate 1a confirmed quote exists in transcript) Transcript source text: confirmed ✓
Three claim types

Every S2 claim must declare one

grounded — Directly supported by a FactList entry. Must cite source_fact_ids.

derived — Calculated or inferred from facts. Must cite source_fact_ids + derivation_note.

interpretive — Editorial judgment. Max ~20% of claims. Auto-passes Gate 2.

Seven fact types

Extracted by S1a across three passes

financial_metric  forward_guidance  management_statement  operational_metric  analyst_question  competitive_reference  prior_quarter_reference

Architecture

Pipeline stages

The pipeline runs in strict sequence. Gates (⊘) are governance checkpoints — they evaluate, accept, reject, or halt. They never generate content. Generation and verification always use different model families.

⊘ Gate 2
Fact Verifier
Mistral-Small-24B

Runs per section. For each claim, checks whether cited FactList facts actually support it: aligned, absent, or contradicted. Pass condition: grounding_score ≥ 0.90 AND contradiction_count == 0. Interpretive claims auto-pass. S2c anchor claims citing analyst_question or prior_quarter_reference auto-pass. Fail → retry up to 2× with failure summary → omit section.

Input S2 sections, locked FactList
Output verified sections + grounding scores
Hard Rule score < 0.90 or contradiction → retry/omit
↓

S6
Editorial Synthesis
Llama-4-Maverick

Writes the opening commentary in FT Lex style — overarching narrative, paradoxes, investor implications. Reads all verified S2 sections. Intentionally runs after Gate 2 so it has access to the complete verified picture. Non-blocking if it fails.

Input verified S2 sections
Output editorial_commentary
↓

S5
Holistic Verifier
DeepSeek-V3.1

Cross-section consistency check using a different model family from generation and Gate 2. Checks for: conflicting claims across sections, mislabeled claim types, misleading framing of neutral facts, investment advice language. If buy/sell/hold language is found → immediate halt, no report released.

Input all verified sections
Output consistency verdict
Hard Rule investment advice language → halt
↓

S7
Business Principles
Llama-4-Maverick + MiniLM-L6-v2

Two-step: (1) LLM generates 6–8 semantic queries from the assembled report, (2) each query retrieves top-5 chunks from a FAISS textbook index (economics and business strategy textbooks), (3) LLM writes the Business Principles section citing retrieved passages. Skipped gracefully if the FAISS index is missing.

Input report, FAISS textbook index
Output econ_expert section

fail

fail

Section fails all Gate 2 retries → omitted from report. Noted in omitted_sections in the JSON artifact.

Graceful degradation: Level 0 (all gates pass, full report) → Level 1 (Gate 2 rejects, retry) → Level 2 (partial output, omit section) → Level 3 (pipeline halt, no output). A FactList failure always triggers Level 3 — no partial output when the foundation is bad.

Theoretical Foundation

Cybernetic frameworks

The architecture is grounded in three cybernetic frameworks adapted for AI systems. These are not metaphors — they are the load-bearing logic behind specific design decisions.

Viable System Model
Multi-layer governance
Stafford Beer

Beer's VSM maps five nested management systems that every viable organism must have. The pipeline maps directly: S1a/S1b are the operational units; Gate 1a and Gate 2 are the coordination layer; S5 is the intelligence layer watching for systemic inconsistency; and the design constraints are the policy layer. Each layer governs only what it can see.

Law of Requisite Variety
Verification must match generation
W. Ross Ashby

Ashby's Law: only variety can destroy variety. A single-model verifier has less variety than the generation system it checks — it will systematically miss the failure modes it shares with the generator. Multi-family verification amplifies the controller's variety to match the full space of generation failures.

Second-Order Cybernetics
Observing the observer
Heinz von Foerster

Von Foerster: the observer is always part of the system it observes. A verification system that uses the same model family as generation creates a closed epistemic loop — the system observes itself and mistakes that for independent confirmation. The structural diversity requirement and the Verification Notes section (which discloses what the system cannot catch) are direct implementations of this principle.

Why cybernetics? Traditional software testing assumes a known correct output. AI generation systems produce outputs that are plausible but not deterministically correct — the failure mode is fluent hallucination, not a crash. Cybernetic frameworks are designed precisely for self-regulating systems that must manage variety, uncertainty, and observer bias. They are the right foundation for this problem class.

Model Configuration

Multi-family verification

Generation and verification must use different model families — always. No family's blind spots carry through the full pipeline.

Role Model Stages Family
Generation Llama-4-Maverick-17B-128E-Instruct-FP8 S0, S1a, S1b, S2a–f, S6, S7 Meta / Llama
Verification A Mistral-Small-24B-Instruct-2501 Gate 1a, Gate 2 Mistral

Technology

Tech stack

Minimal dependencies chosen for reliability and auditability, not ecosystem popularity.

Orchestration
Python + asyncio

Pipeline orchestration with asyncio.gather() for parallel S2 agents.

LLM API
Together AI

OpenAI-compatible endpoint for all LLM calls. Swap models by changing a config string.

Data contracts
Pydantic

Typed schemas for every inter-stage artifact. Invalid data raises at the boundary, not downstream.

Transcript fetching
EDGAR / Finnhub / FMP

Auto-cascade: tries EDGAR first, then Finnhub, then FMP. Local PDF also supported via PyMuPDF.

Market data
yfinance + Alpha Vantage

Historical financials, stock reaction, EPS consensus estimates for S0 context assembly.

Vector search
FAISS + sentence-transformers

IndexFlatL2 over 500-word overlapping textbook chunks for S7 economic retrieval.

PDF output
Node.js + docx-js

format_report.js builds the Word doc; report_formatter.py converts to PDF.

Charts
Matplotlib

7-dimension radar chart and trend chart, embedded as PNGs in the PDF brief.

GUI
Streamlit

Optional web interface: upload transcript, stream live logs, download PDF.
