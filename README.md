# Chorus AI Systems — Earnings Call Dossier

A multi-agent Python pipeline that transforms an earnings call transcript into a verified analytical brief styled after Financial Times / Lex editorial quality.

**Core architectural commitment: trust is structural, not a model property.** Every factual claim in the output traces back to a verbatim quote from the transcript through an immutable FactList. Nothing advances between pipeline stages without a governance gate check.

Built by Daniel Wipert as part of the Chorus AI Systems portfolio.

## What This Produces

Given an earnings call transcript, the pipeline outputs:

- A structured `report_output.json` with all verified claims, grounding scores, and metadata
- A formatted PDF brief (`{TICKER}_Q{Q}_{YEAR}_Brief.pdf`) with magazine-quality layout

The PDF contains:
1. Editorial Commentary — FT Lex-style opening synthesis
2. Business Narrative — strategic context and execution analysis
3. Signals & Thesis — investment themes, risks, catalysts
4. Management Gaps — deflected questions, unfulfilled commitments
5. Competitive Positioning — peer benchmarking (when context is available)
6. Financial Snapshot — key metrics table with YoY changes
7. Radar Chart — 7-dimension visual scorecard
8. Business Principles — textbook-grounded economic analysis of the company's choices
9. Verification Notes — grounding scores, omitted sections, safety flags

## How to Run

### Command line

```bash
# Fetch transcript from SEC EDGAR and run full pipeline
python pipeline.py --ticker FDX --year 2026 --quarter 3

# Use a local PDF or TXT transcript
python pipeline.py --transcript testing/fedex.pdf

# Use local file AND fetch context (historical data, peers)
python pipeline.py --transcript testing/fedex.pdf --ticker FDX --year 2026 --quarter 3

# Include peer tickers for competitive intelligence
python pipeline.py --ticker FDX --year 2026 --quarter 3 --peers UPS,XPO

# Skip context assembly for faster runs
python pipeline.py --transcript testing/fedex.pdf --no-context

# Force a specific transcript source
python pipeline.py --ticker MSFT --year 2026 --quarter 2 --source finnhub

# Specify output path
python pipeline.py --ticker FDX --year 2026 --quarter 3 --output outputs/fdx_q3.json
```

### All CLI flags

| Flag | Description | Required |
|---|---|---|

## Pipeline Architecture

The pipeline runs in this exact sequence. Gates (⊘) are governance checkpoints — they evaluate, accept, reject, or halt. They never generate content.

```
TRANSCRIPT INPUT
     │
     ▼
S0:  Context Assembly        — Fetches historical financials, stock reaction, peer summaries
     │                          (skipped if no --ticker/--year/--quarter or --no-context)
     ▼
S1a: Fact Extractor          — 3-pass targeted extraction; every fact gets a verbatim quote
     │
     ▼
⊘ Gate 1a: FactList          — Validates quote fidelity; ≥80% required to continue
  Validation                    FactList is LOCKED after this gate passes
     │
     ▼ (HALT if <80% fidelity)
S1b: Structured Data Pull    — Organizes financials from FactList into snapshot tables
     │
     ▼
     ┌──────────────────────────────────────┐
     │        S2 AGENTS (PARALLEL)          │
     │  S2a: Business Narrative             │
     │  S2b: Signals & Thesis               │
     │  S2c: Management Gaps & Omissions    │
     │  S2f: Competitive Intelligence       │
     └──────────────────────────────────────┘
     │
     ▼
⊘ Gate 2: Fact Verifier      — Verifies every claim against FactList (per section)
     │                          Retry up to 2x per section; omit section after that
     ▼
S6:  Editorial Synthesis     — FT Lex-style opening commentary (The Lex Writer)
     │
     ▼
S5:  Holistic Verifier       — Cross-section consistency + investment advice scan
     │
     ▼ (HALT if safety flag triggered)
S7:  Business Principles     — Query generation → FAISS textbook retrieval → expert writing
     │
     ▼
OUTPUT: report_output.json → PDF via report_formatter.py
```

### Stage Details

#### S0 — Context Assembly
Runs when `--ticker`, `--year`, and `--quarter` are provided. Fetches:
- 3 prior quarters of financial history (yfinance)
- Post-earnings stock price reaction (yfinance)
- EPS consensus estimates (Alpha Vantage, if key set)
- Prior quarter transcript summaries from SEC EDGAR (up to 3 quarters back)
- Peer company transcript summaries (if `--peers` provided)

Non-blocking — missing data is logged but never halts the pipeline.

#### S1a — Fact Extractor
Three targeted passes over the transcript:
- **Pass 1:** `financial_metric`, `forward_guidance`
- **Pass 2:** `management_statement`, `operational_metric`
- **Pass 3:** `analyst_question`, `competitive_reference`, `prior_quarter_reference`

Each fact requires a `verbatim_quote` (character-exact from transcript) and `speaker`. Duplicates removed by quote matching.

#### Gate 1a — FactList Validation
- **≥90% pass rate:** Proceed normally
- **80–89% pass rate:** Strip failing facts, proceed at Level 1 degradation
- **<80% pass rate:** Hard halt — FactList failure poisons everything downstream

After Gate 1a passes, **the FactList is immutable**. No downstream agent may add, modify, or remove facts.

#### S1b — Structured Data Pull
Reads the locked FactList and produces the financial snapshot: key metrics table (with YoY changes and vs-estimate comparisons), headline, and 3–5 key takeaways. Sector overridden with authoritative yfinance GICS classification.

#### S2a / S2b / S2c / S2f — Analysis Agents (Parallel)
All four run simultaneously via `asyncio.gather()`. Each receives the transcript, FactList, and optional context bundle.

| Agent | Section | Focus |
|---|---|---|
| S2a | Business Narrative | Strategic context, execution, market position |
| S2b | Signals & Thesis | Investment themes, risks, catalysts, momentum |
| S2c | Management Gaps | Deflected analyst questions, unfulfilled prior commitments |
| S2f | Competitive Intelligence | Peer benchmarking, positioning vs. competitors |

Every claim must be labeled `grounded`, `derived`, or `interpretive` (see FactList section).

#### Gate 2 — Fact Verifier
Runs per section. For each claim, checks whether cited FactList facts actually support it:
- `aligned` — cited facts directly support the claim
- `absent` — cited facts don't address the claim
- `contradicted` — cited facts directly contradict the claim

**Pass condition:** grounding_score ≥ 0.90 AND contradiction_count == 0

Built-in fairness coercions:
- `interpretive` claims auto-pass (editorial judgment is not fact-verifiable)
- S2c anchor claims citing `analyst_question` or `prior_quarter_reference` facts auto-pass (question existence IS the grounding)

**Retry logic:** Fail → regenerate section with failure summary → retest (max 2 retries) → omit section if still failing.

#### S6 — Editorial Synthesis
Writes the opening commentary in FT Lex style — overarching narrative, paradoxes, investor implications. Reads all verified S2 sections. Non-blocking if it fails.

#### S5 — Holistic Verifier
Cross-section consistency check using a **different model family** from generation and Gate 2. Checks for:
- Conflicting claims across sections
- Mislabeled claim types
- Misleading framing of neutral facts
- Investment advice language (buy/sell/hold → immediate halt)

#### S7 — Business Principles
Two-step process:
1. LLM generates 6–8 targeted semantic queries from the assembled report
2. Each query retrieves top-5 chunks from the FAISS textbook index
3. LLM writes the "Business Principles" section citing retrieved passages

Skipped gracefully if the knowledge base index is missing.

## The FactList — Most Important Concept

The FactList is the locked, immutable foundation of the entire pipeline.

```
Final report claim
       ↓  (S2 claim cites source_fact_ids)
FactList entry F012
  verbatim_quote: "adjusted EPS increased 16 percent year-over-year"
  speaker: "Raj Subramaniam, President and CEO"
       ↓  (Gate 1a confirmed quote exists in transcript)
Transcript source text: confirmed ✓
```

**Three claim types — every S2 claim must declare one:**

| Type | What it means | Requirement | Gate 2 treatment |
|---|---|---|---|
| `grounded` | Directly supported by a FactList entry | Must cite `source_fact_ids` | Verdict from fact relevance |
| `derived` | Calculated or inferred from facts | Must cite `source_fact_ids` + `derivation_note` | Verdict from derivation soundness |
| `interpretive` | Editorial judgment | Must be labeled as such; max ~20% of claims | Auto-passes (not fact-verifiable) |

**Seven fact types S1a extracts:**

| Type | What it captures |
|---|---|
| `financial_metric` | Revenue, EPS, margins, CapEx — any quantitative financial figure |
| `management_statement` | Qualitative assertion by a named executive |
| `forward_guidance` | Any forward-looking projection or target |
| `analyst_question` | Questions posed during Q&A (enables gap analysis in S2c) |
| `competitive_reference` | Any mention of competitors or market position |
| `operational_metric` | Non-financial operating data (volumes, units, usage metrics) |
| `prior_quarter_reference` | References to prior quarter data or prior commitments |

## Graceful Degradation

| Level | Name | Trigger | Behavior |
|---|---|---|---|
| **0** | Normal | All gates pass | Full report, all sections |
| **1** | Retry | Gate 2 rejects a section | Regenerate with failure summary; max 2 retries per section |
| **2** | Partial Output | Section fails all retries; or S0/S6/S7 error | Omit section; note in `omitted_sections`; continue |
| **3** | Pipeline Halt | Gate 1a <80%; or S5 safety flag; or >2 sections fail | No output; halt reason logged |

A FactList failure (Gate 1a) **always** triggers Level 3. No partial output when the foundation is bad.

## Model Configuration

**Key principle: generation and verification must use different model families.** No family's blind spots carry through the full pipeline.

| Role | Model | Stages |
|---|---|---|
| Generation | `meta-llama/Llama-4-Maverick-17B-128E-Instruct-FP8` | S0, S1a, S1b, S2a–f, S6, S7 |
| Verification A | `mistralai/Mistral-Small-24B-Instruct-2501` | Gate 1a, Gate 2 |
| Verification B | `deepseek-ai/DeepSeek-V3.1` | S5 (holistic verifier) |
| Embedding | `sentence-transformers/all-MiniLM-L6-v2` | S7 (FAISS retrieval) |

All LLM calls go via Together AI's OpenAI-compatible endpoint:

```python
from openai import OpenAI
client = OpenAI(
    api_key=os.getenv("TOGETHER_API_KEY"),
    base_url="https://api.together.xyz/v1"
)
```

## Transcript Sources

The pipeline supports four transcript sources. With `--source auto` (default), it tries them in order: EDGAR → Finnhub → FMP.

| Source | Key Required | Notes |
|---|---|---|
| **SEC EDGAR** | None (free) | Works best for companies that file 8-K exhibits with earnings call transcripts. Large-caps (AAPL, MSFT) typically don't. Works well for: FDX, MCD, financials, REITs. |
| **Finnhub** | `FINNHUB_API_KEY` | Recommended. Free tier: 60 calls/min. Reliable coverage. |
| **FMP** | `FMP_API_KEY` | Comprehensive but requires paid plan ($149/mo+). |
| **Local file** | None | Pass `--transcript file.pdf` or `--transcript file.txt`. PDF text extracted via PyMuPDF. Can be combined with `--ticker` for context assembly. |

## Knowledge Base Setup (S7)

S7 (Business Principles) retrieves relevant passages from economics and business strategy textbooks using FAISS. The index must be built once before S7 will produce citations.

```bash
# 1. Place textbook PDFs in the textbooks/ directory

# 2. Build the index (10–20 min on CPU, one-time)
python knowledge_base.py

# 3. Verify with smoke test
python knowledge_base.py --test
```

The index is saved to `knowledge_base/textbooks.index` and `knowledge_base/metadata.json`. If these files are missing, S7 is skipped gracefully (the report is generated without the Business Principles section).

**Index details:**
- Embedding model: `all-MiniLM-L6-v2` (384-dim, runs locally)
- Index type: FAISS `IndexFlatL2` (exact L2 distance)
- Chunking: 500-word overlapping spans (50-word overlap) per page

## Design Constraints

These are architectural commitments — not preferences. Do not work around them.

- **No unverified output.** If the verification pipeline is unavailable, halt. No fallback to unverified generation.
- **No investment advice.** S5 scans for buy/sell/hold language. If found → Level 3 halt, no report released.
- **No fabricated quotes.** If a verbatim quote can't be confirmed in the transcript → reject the fact at Gate 1a.
- **Generation and verification must use different model families.** Always. No exceptions. This is the primary defense against blind spot propagation.
- **FactList is immutable after Gate 1a.** No downstream agent may add, modify, or remove facts.
- **Verification limitations must be disclosed.** Every report includes what the verification system can and cannot catch. The system observes its own observation process.

## Theoretical Foundation

The architecture is grounded in three cybernetic frameworks adapted for AI systems:

- **Beer's Viable System Model** → multi-layer pipeline structure with independent governance at each layer
- **Ashby's Law of Requisite Variety** → verification capacity must match generation complexity; multi-model, multi-family verification amplifies the controller's variety
- **Von Foerster's Second-Order Cybernetics** → the system must observe its own observation processes; observers (Gate 2, S5) must be structurally diverse to avoid shared blind spots
